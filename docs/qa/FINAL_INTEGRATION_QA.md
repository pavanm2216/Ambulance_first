# Ambulance First — Final Integration & QA Gate

## Scope
This gate validates the controlled workflow implementation from Phases 6–10 without bypassing Supabase security.

## Deployment order
1. Apply `docs/migrations/PHASE_7_PRICING_SETTINGS.sql` if `pricing_settings` is absent.
2. Apply `docs/migrations/PHASE_6_CONTROLLED_WORKFLOW.sql`.
3. Apply `docs/migrations/PHASE_7_10_CONTROLLED_OPERATIONS.sql`.
4. Run the smoke queries in `FINAL_SUPABASE_SMOKE_TEST.sql`.
5. Test the RPCs using real accounts for each role.
6. Only after successful RPC tests, apply the reviewed RLS replacement.
7. Deploy `supabase/functions/admin-provision-staff` separately with server-side secrets.
8. Run Flutter validation locally.

## Role smoke matrix
- CUSTOMER: create booking; read own booking; accept/reject quotation.
- CUSTOMER_CARE: allowed verification transitions only.
- TEAM_LEAD: prepare quotation; allocate resources; allowed allocation transitions.
- DRIVER: only assigned booking status transitions.
- DOCTOR: only assigned booking assessments/vitals/completion.
- ADMIN: administrative read and controlled quotation/allocation operations.

## Security checks
- No service-role key in Flutter.
- No direct client-side mutation of protected workflow fields after RLS cutover.
- `*_open` policies remain until RPC tests pass.
- Audit rows are generated by trusted RPCs.
- Historical staff deletion is not exposed.
- EMT is not treated as an active profile role unless a real `profiles.role='EMT'` row exists.

## Local Flutter validation
Run from the project root on a machine with Flutter SDK:

```powershell
flutter --version
flutter pub get
flutter analyze
flutter test
flutter build web --release --dart-define=SUPABASE_ANON_KEY=<publishable-key>
```

If Android release is required:

```powershell
flutter build apk --release --dart-define=SUPABASE_ANON_KEY=<publishable-key>
```

Do not place a service-role key in any `--dart-define` or app configuration.

## Known non-claims
This packaging environment cannot execute Flutter CLI or connect to the user's Supabase project. Therefore runtime build success and live RPC success remain deployment-side gates.
